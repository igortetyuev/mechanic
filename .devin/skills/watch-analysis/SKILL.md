# Анализ работы часов таймграфером

## Оборудование и подключение

- Устройство из этого репозитория (`pio run -e esp32dev -t upload`), подключено по USB.
- Порт: найти через `ls /dev/cu.usbserial*`. Скорость 115200.
- **Открытие порта сбрасывает ESP32** (DTR) — статистика начинается заново при каждом новом соединении.
- После ресета приёмник слушает левый слот I2S. Если микрофон SPH0645 или L/R подтянут к VDD — сразу после подключения отправить `ch`.
- Проверка живости: команда `dbg` — `пол` должен быть > 0, `событий`/`ударов` должны расти при тикающих часах.

## Скрипт замера

Не использовать `pio device monitor` в фоне — собирать вывод скриптом:

```bash
~/.platformio-venv/bin/python -c "
import serial, time
s = serial.Serial('/dev/cu.usbserial-0001', 115200, timeout=1)
time.sleep(2.5)              # даём плате загрузиться после ресета
s.reset_input_buffer()
s.write(b'ch\n')             # раскомментировать, если микрофон в правом слоте
time.sleep(0.3)
s.write(b'rst\n')            # чистая статистика под новый замер
t0 = time.time()
while time.time() - t0 < 150:
    line = s.readline()
    if line:
        print(line.decode('utf-8', 'replace').rstrip())
" 2>&1 | tail -40
```

## Процедура замера

1. **Завести часы до упора** — ход сильно зависит от завода.
2. Для каждого положения:
   - положить часы в нужную позицию, микрофон прижать к корпусу (со стороны стекла/циферблата звук громче, чем через заднюю крышку);
   - подождать 15–20 с — затихнут переходные шумы от перекладки;
   - отправить `rst`, собирать 120–150 с;
   - результат — последние ~5 строк отчёта (EMA и буфер догоняют реальное значение ~60–90 с после `rst`).
3. **Порядок положений** (минимум — первые два):
   - стеклом вверх (dial up);
   - стеклом вниз (dial down) — внимание: слышимость хуже, `мимо` может вырасти;
   - головкой вверх, головкой вниз, 12 вверх, 12 вниз (вертикальные позиции, если нужен полный профиль).
4. Дополнительно: повторить замер стеклом вверх через несколько часов на просевшем заводе — разница покажет амплитудную зависимость.

## Формат отчёта

```
ПК/Ч 21582 (авто 21600) | -0.07% | -58.1 сек/сут | отстаёт -> УМЕНЬШИТЬ период | разнобой +1.5 мс | ударов 501, мимо 144
```

- `ПК/Ч` — измеренный ритм (сглаженный EMA), в скобках номинал (`авто` — определён автоматически, `ном` — задан командой `bph`);
- `сек/сут` — отклонение хода (+ спешит / − отстаёт);
- указание — куда крутить регулятор;
- `разнобой` — разница полуходов тик/так; **при `мимо` > 10 % паритет сбивается, знаку не доверять**;
- `ударов`/`мимо` — принятые/отброшенные интервалы. `мимо` > 20 % — микрофон плохо слышит или много ложных событий.

## Интерпретация

- |ход| до ±20 сек/сут — хороший результат; ±30–60 — приемлемо для недорогих механизмов.
- Позиционный разброс (макс−мин хода по положениям) < 30 сек/сут — норма; > 100 — вероятна низкая амплитуда/износ, сервис.
- Зависимость от завода > 50 сек/сут (полный vs просевший) — низкая амплитуда баланса: засохшая смазка, слабая заводная пружина, износ опор.
- Разнобой < 1 мс — норма; > 1.5 мс — спуск требует регулировки.
- Показания ±сотни сек/сут в первые ~30 с после `rst` — мусор от перекладки часов в буфере, не результат.

## Типичные проблемы

- `интервалов 0` долго — не тот слот (`ch`), микрофон не слышит или часы стоят. Проверить `dbg`.
- `мимо` растёт быстрее ударов — слабый сигнал: прижать микрофон плотнее, переложить на стекло.
- Отчёты зависли (ударов не растёт) — часы остановились или микрофон отъехал.
